# ESP32-C3 BLE MIDI 控制器 · 按键配置串口协议

对应固件：[firmware/esp32c3-custom-control.bin](firmware/esp32c3-custom-control.bin)

供上位机（Electron 应用）通过 USB 配置 8 个按键的 `sendControlChange` 参数。

## 0. 设备识别

`ping` 响应里的 `product` 字段固定为 `"pocket-master-custom-control"`。上位机**必须**校验该字段，
只有匹配才认作本设备，否则视为“没有找到设备”，继续尝试其他串口。

这样可以避免误连到同一台电脑上其他 ESP32 项目（它们同样使用 USB CDC 串口，也会回 JSON）。

---

## 1. 连接与前置条件

| 项目 | 值 |
| --- | --- |
| 板子 / FQBN | `esp32:esp32:AirM2M_CORE_ESP32C3:CDCOnBoot=cdc` |
| 串口 | 115200 bps，8 数据位，无校验，1 停止位（8N1） |
| 帧格式 | 每行一条紧凑 JSON，以 `\n`（LF）结束；`\r` 会被忽略 |
| 最大行长 | 256 字节（超出部分丢弃） |
| 传输接口 | ESP32-C3 原生 USB-Serial/JTAG 虚拟串口（非 UART0） |

> **必须**在编译时启用 “USB CDC On Boot”（FQBN 里的 `:CDCOnBoot=cdc`）。
> 若不启用，`Serial` 是 UART0（GPIO20/21），USB 口上收不到任何数据。

固件在 `loop()` 中始终轮询串口，**与 BLE 是否连接无关**，任何时候都可以配置。

---

## 2. 数据模型

8 个按键，每个按键一组参数：

| 字段 | 类型 | 取值 | 说明 |
| --- | --- | --- | --- |
| `key` | int | `1` – `8` | 按键序号（对应固件里的 KEY1–KEY8） |
| `cc` | int | `0` – `127` | MIDI Control Change 控制器号 |
| `value` | int | `0` – `127`，或 `255` | 按下时发送的 CC 值；`255` 表示“切换”（见下） |
| `channel` | int | `1` – `16` | MIDI 通道 |

存储位置：NVS 命名空间 `midicfg`，键名 `keys`，二进制 8 × 3 = 24 字节。

### 2.1 `value = 255`：切换模式

对“开关”类功能（如调音表开关、鼓机界面开关），除了固定发 `0`（关）或 `127`（开），
还可以把 `value` 设为 `255`，表示**切换**：设备每次按下该按键时，在 `0` / `127` 之间交替发送，
首次按下发 `127`。

```
按下第 1 次 -> 发送 127
按下第 2 次 -> 发送 0
按下第 3 次 -> 发送 127
...
```

切换状态只存在设备内存里（`bool toggleState[8]`），**设备重启后会重置为“下一次发送 127”**。
它由上位机在“功能取值”下拉里选择“切换”时写入。

默认值（出厂 / `reset` 后的状态）：

| key | cc | value | channel | 用途 |
| --- | --- | --- | --- | --- |
| 1 | 24 | 0 | 1 | Preset - |
| 2 | 25 | 0 | 1 | Preset + |
| 3 | 58 | 0 | 1 | Tuner GUI Off |
| 4 | 58 | 127 | 1 | Tuner GUI On |
| 5 | 92 | 0 | 1 | Drum GUI Off |
| 6 | 92 | 127 | 1 | Drum GUI On |
| 7 | 93 | 0 | 1 | Drum Stop |
| 8 | 93 | 127 | 1 | Drum Play |

---

## 3. 生效时机

- `set` / `reset` 只写 NVS，**不立即改变当前运行时行为**；
- 设备**重启（断电重上电或复位）后**，`setup()` 读一次 NVS 并生效。
- 如需上位机引导用户“配置完成后重启设备”，请在 UI 上明确提示。

---

## 4. 命令一览

上行（上位机 → 设备），`cmd` 字段为命令名：

| cmd | 额外字段 | 说明 |
| --- | --- | --- |
| `ping` | 无 | 探测设备是否在线 |
| `get` | 无 | 读取当前全部配置 |
| `set` | `key`, `cc`, `value`, `channel` | 修改单个按键 |
| `reset` | 无 | 恢复出厂默认值 |

下行（设备 → 上位机），每条响应都是一个 JSON 对象，含 `ok` 字段：

- 成功：`{"ok":true, "cmd":"<命令名>", ...}`
- 失败：`{"ok":false, "cmd":"<命令名>", "error":"<原因>"}`

---

## 5. 请求 / 响应示例

### 5.1 ping

请求：

```json
{"cmd":"ping"}
```

响应：

```json
{"ok":true,"cmd":"ping","product":"esp32c3-ble-midi-host"}
```

### 5.2 get

请求：

```json
{"cmd":"get"}
```

响应（`keys` 数组固定 8 项，顺序即 `key` 1→8）：

```json
{"ok":true,"cmd":"get","keys":[{"key":1,"cc":24,"value":0,"channel":1},{"key":2,"cc":25,"value":0,"channel":1},{"key":3,"cc":58,"value":0,"channel":1},{"key":4,"cc":58,"value":127,"channel":1},{"key":5,"cc":92,"value":0,"channel":1},{"key":6,"cc":92,"value":127,"channel":1},{"key":7,"cc":93,"value":0,"channel":1},{"key":8,"cc":93,"value":127,"channel":1}]}
```

### 5.3 set

请求（一次只改一个按键）：

```json
{"cmd":"set","key":1,"cc":30,"value":64,"channel":2}
```

响应：`cmd` 为 `"set"`，同时回显**改完之后的全表**（省掉一次 `get`）：

```json
{"ok":true,"cmd":"set","keys":[{"key":1,"cc":30,"value":64,"channel":2}, ...其余 7 项...]}
```

出错的几种响应：

```json
{"ok":false,"cmd":"set","error":"need key,cc,value,channel"}
{"ok":false,"cmd":"set","error":"out of range"}
```

### 5.4 reset

请求：

```json
{"cmd":"reset"}
```

响应：`cmd` 为 `"reset"`，回显默认全表：

```json
{"ok":true,"cmd":"reset","keys":[...第 2 节默认值...]}
```

### 5.5 错误含义

| error | 触发条件 |
| --- | --- |
| `invalid json` | 该行不是合法 JSON，或不是 JSON 对象 |
| `missing cmd` | JSON 合法但没有 `cmd` 字段 |
| `need key,cc,value,channel` | `set` 缺少必需字段 |
| `out of range` | 任一字段超出第 2 节的取值范围 |
| `unknown cmd` | `cmd` 不认识 |

> 以上除 `invalid json` / `missing cmd` 外，`cmd` 字段都会原样回传。

## 6. 上位机实现要点

1. **行解析**：按 `\n` 切分累积缓冲区，逐行 `JSON.parse`。
2. **过滤非协议行**：BLE-MIDI 库自身的调试日志和固件自身的配置日志（`[学习] ...`、`[配置] ...`）都打在同一个串口上，是纯文本行。
   建议只接受**以 `{` 开头且含 `"ok"` 字段**的行作为响应。
3. **应答匹配**：协议无请求 id；按“发送后读取下一条合法响应”即可（`set`/`reset` 的响应里带 `cmd` 可做校验）。
4. **超时重试**：等待响应建议 500–1000 ms 超时；设备 `loop()` 里有 2 ms 延迟，正常响应会很快。
5. **打开串口可能引起复位**：ESP32-C3 原生 USB 串口在主机切换 DTR/RTS 时可能触发芯片复位。建议打开端口时显式设置 `dtr: false`、`rts: false`，并在 `open` 后延迟数百毫秒再发第一条命令。
6. **推荐流程**：`ping` 确认在线 → `get` 拉取当前配置 → 用户在 UI 里编辑 → 对每个改动的按键发一次 `set` → 提示用户重启设备生效。

Node.js 侧可用的串口库：`serialport`（配合 `@serialport/parser-readline` 做行解析）。

---

## 7. 已知限制

- `set` 不支持一次改多个按键，上位机需循环发送。
- 配置生效需要重启设备。
- 目前仅此固件（ESP32-C3）实现该协议；nRF52832 版本尚未移植。
